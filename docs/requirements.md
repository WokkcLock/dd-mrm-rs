# dd-mrm 需求与功能清单

来源：旧项目 DdModTool 的实际能力（minimal-fix 分支，热修改 v2.1 实测成功态）+
用户在重写讨论中给出的方向。本文是迁移的验收基准。

## 1. 一句话

Darkest Dungeon 存档 mod 管理器：离线改档 + 游戏运行中热修改，字节级保真。

## 2. 功能需求

| # | 需求 | 说明 |
|---|---|---|
| FR1 | 存档列表 | 9 个 profile 槽：estate 名、mod 数、DLC 态；从 persist.game.json 解析 |
| FR2 | 可用 mod 列表 | 扫描游戏 mods 目录 + Steam 创意工坊（appid 262060）；手动刷新、打开目录 |
| FR3 | 存档 mod 列表 | 目标档已应用 mod：增/删/换/排序（顺序即列表序） |
| FR4 | 应用（离线） | 游戏未运行：bit31 保真写盘 + 原子写（临时文件 + 替换） |
| FR5 | 应用（热） | 游戏运行且停存档列表：注入 DLL → 改信封内存 → 游戏自落盘（docs/hotapply-design.md） |
| FR6 | 多轮热修改 | 退列表→改→再进档，无限次；列表停留期可连续应用 |
| FR7 | 预设 | 保存/加载 mod 组合 |
| FR8 | 备份 | 应用前自动备份为 zip（SaveBak/{档名}_{时间戳}.zip，可手工解压恢复——与旧工具一致，无内置恢复 UI） |
| FR9 | 状态栏 | 应用结果四态反馈 + 失败细节（净化后展示） |
| FR10 | dsoncli | 编解码 CLI：parse/dump/rewrite/roundtrip（dd-mrm-dson 双 target） |

不做（Non-goals）：frida 引擎路线；战役内（镇/raid）修改；hero 等 17 存档文件的
编辑（类型白名单外，见 dson-bit31-notes.md §5）；自动发现 Steam 安装（首版配置
文件写死路径）。

## 3. 非功能需求

- **保真**：同内容重写字节一致；既有条目 bit31 逐位保留。
- **崩溃零容忍**：任何护栏不过→拒绝+报告，绝不盲写游戏内存。
- **日志自治**：所有引擎/注入/应用事件落 `logs/engine.log`，排障不依赖用户复制。
- **轻量**：slint（用户指定，内存/存储开销理由）；无守护进程、无轮询。
- **UI 保持三列表骨架**（存档列表 / 可用 mod 列表 / 存档 mod 列表），其余按成熟
  桌面模式重设计（用户原话：现有 UI 是自己设计的，很不成熟，按更成熟的设计优化）。

## 4. 旧项目遗留的已知未验证点（迁移时清账）

- bit31 新条目启发式 = 2 文件归纳（dson-bit31-notes.md §2）→ 遇未知结构拒绝写。
- 清空全部 mod 使 applied_ugcs 字段消失：**已实测容忍**（v2.1 验证轮 count=0 +
  信封重建空向量合法）。
- 旧 master 的 WaitForSyncedAsync 无新鲜度检查——frida 路线废弃，随之路径消失。
